## 1. 项目是什么

STM32H743VIT6 自制飞控。当前阶段：**传感器 + 姿态 + 健康 + 校准 + Flash 参数 + 接收机解析 + OSD 驱动 + 电机输出 + 上位机**。
还没有：飞行控制、电机输出、PID、失效保护、电池电压/电流检测。

- MCU：STM32H743VIT6，480MHz，2MB Flash（链接脚本只给代码 1920K，最后 128KB 留给参数）
- 无 RTOS，协作式调度器（DWT 微秒计时）
- 上位机：PyQt5 + pyqtgraph，走 USB CDC

| 外设 | 型号 | 总线 / 引脚 | 状态 |
|---|---|---|---|
| IMU | ICM42605 | SPI1，CS=PC15 | 1kHz 读取，已跑通 |
| IMU2 | ICM42605 | SPI4，CS=PC13 | 只初始化，不读取 |
| MAG | QMC5883P | I2C1，0x2C | 100Hz，已跑通 |
| BAR | DPS310 | I2C2，0x76 | 50Hz，已跑通 |
| OSD | AT7456E | SPI2：SCK=PB13，MISO=PB14，MOSI=PB15，CS=PB12 | 检测/初始化/清屏通过，**还不会显示内容** |
| 接收机 | ELRS（CRSF） | USART6：TX=PC6，RX=PC7，420000 8N1，RX 用 DMA1_Stream0 | 代码就绪，**真机未验证** |
| 调试口 | USB CDC | OTG_FS | `printf` 已重定向 |

| 任务 | 周期 | 优先级 | 作用 |
|---|---|---|---|
| `SIMULATOR` | 1ms | REALTIME | **仅 `USE_SIM`**：机体模型 + 合成传感器 |
| `IMU_READ` | 1ms | REALTIME | 读 ICM42605（**仅非仿真**） |
| `AHRS_EST` | 1ms | HIGH | 应用校准 → `AHRS_Update`（姿态估计） |
| `PVRS_EST` | 5ms | HIGH | `PVRS_Update` 位置/速度预测；未解锁时再加 `PVRS_Still` |
| `FLT_CTRL` | 1ms | HIGH | 自稳角度环 → 角速度环 → 混控 → `Motor_Set` |
| `MAG_READ` | 10ms | MED | 读 QMC5883P（仅非仿真） |
| `BAR_READ` | 20ms | MED_LOW | 读 DPS310（仅非仿真） |
| `SENSOR_CAL` | 1ms | LOW | `Cal_Run` 校准状态机 |
| `PROTOCOL` | 10ms | LOW | `Prot_Run` 收命令（`rc` / `arm` / `cal`） |
| `LED` | 1s | LOW | 翻转 LED1 |

- AHRS：Mahony，加速度 + 磁力计修正；`AHRS.Yaw/Roll/Pitch` 单位弧度；加速度修正带门控（`|A|−g < 0.3`）。
- 姿态控制：**自稳常开**（角度外环 + 角速度内环），偏航只有角速度环；**定高**（气压计 → 升降速度 → 总油门）。
- 解锁：上电默认 `DISARM`，收到 `arm,1` 才输出；未解锁时 `Flight_Update()` 第一句就 `Motor_Stop()`。
- 健康：一个 `health_t` 管**两种失败**——**数值卡死**（连续读到相同值就计数）和**超时没数据**
  （`Timeout` 毫秒内没 `Health_Update` 过）。`Health_Status()` 两种都查，任一失败就返回 false；
  `Timeout = 0` 表示不判超时（IMU/磁/气压都用 0，它们本来就一直在读，靠卡死检测就够了）。
  `OFL_Health`（光流+激光，Optical Flow and Laser）用 `Limit 3000 / Timeout 200`——光流在地面静止时
  数值本来就可能是常数，所以卡死阈值放得很松，真正管用的是 200ms 超时。
- 遥测：`main.c` 的三个调试宏（`USER_DEBUG_AHRS` / `USER_DEBUG_DEVICE` / `USER_DEBUG_HOST_TOOL`）**默认全注释**；
  仿真时由 `Simulator.c` 每 20ms 打一行 13 字段 `SIM,...`（见 §15.4）。
- 校准参数：成功后写 bank2 最后一个扇区（单槽 + CRC32），上电由 `Flash_Load()` 加载。
- 接收机：USART6 + DMA 空闲中断，解析后写 `RC_Data`；`Receiver_Status()` 判连接。
- OSD：上电检测、初始化、清屏。
- 电机：上电即按 DShot300 连续输出 0 油门，两路定时器各一条 DMA 流突发写 CCR（示波器已验收）。

## 4. 上位机通信协议

命令：

```
cal,imu,start
cal,imu,next
cal,imu,abort
cal,mag,start
cal,mag,abort
rc,<油门>,<偏航>,<横滚>,<俯仰>   # 虚拟遥控，50Hz 连发；油门 0~1000，杆量 −100~100
```

> 解锁/油门注入**本来没有**上位机命令（2026-11-05 决定）：台架阶段直接改 `Flight.c` 里的静态变量或用调试器调用。
>
> 例外：`rc,...` 是 2026-11-08 加的**虚拟遥控**，把上位机两个虚拟摇杆当接收机用。
> 它只写 `RC_SetThro` / `RC_SetRoll` / `RC_SetPitch` / `RC_SetYawRate`（和将来 CRSF 通道同一套 setpoint），不动解锁状态。
> 满杆角速度 `MAX_RATE = 200°/s`。`rc` 里的油门现在是**升降速度**语义（中位 500 = 定高），不再是"油门千分比"。
>
> 解锁是单独一条命令 `arm,<0|1>`（见 §13.7）。**旧的 200ms 超时回中代码已由用户删除**，
> 现在上位机断开后固件保持最后一帧杆量——恢复 CRSF 时要重新加上（接收机失联必须回中）。

回包：

```
CAL,IMU,CHECK
CAL,IMU,COLLECT,FACE1 ... FACE6
CAL,IMU,WAIT,FACE2 ... WAIT,GYRO
CAL,IMU,COLLECT,GYRO
CAL,IMU,DONE
CAL,IMU,SAVE,ERROR
CAL,IMU,ERROR
CAL,IMU,IDLE,ABORTED
CAL,IMU,BUSY

CAL,MAG,COLLECT
CAL,MAG,DONE
CAL,MAG,SAVE,ERROR
CAL,MAG,ERROR
CAL,MAG,IDLE,ABORTED
CAL,MAG,BUSY
```

注意：

- 固件 `Cal_Start` 同时处理 `START` 和 `NEXT`；IMU 在 `WAIT` 时表示"继续"，否则表示"开始"。
- MAG 不进入 `WAIT`，启动后自动采 1000 点。
- `ERROR` = 校准失败，不区分错误码。
- `SAVE,ERROR` = 校准成功但 Flash 保存失败，校准标志被清除，需要重新校准。
- 固件入口函数是 `Prot_Run()`（从 `Prot_Receive` 改名），任务表里已同步。

## 5. 接收机（ELRS / CRSF）

### 5.1 链路

- 硬件：USART6，TX=PC6，RX=PC7，**420000 8N1**（在 CubeMX 里配的，代码不再覆盖）。
- 接收：`HAL_UARTEx_ReceiveToIdle_DMA` + `DMA1_Stream0`（NORMAL 模式）+ 空闲中断。
- DMA 是 NORMAL 模式，**每次空闲中断后 HAL 会停掉传输**，所以 `HAL_UARTEx_RxEventCallback` 里必须重新 `Receiver_Start()`；`HAL_UART_ErrorCallback` 里也要重挂，否则一次溢出/噪声就永久收不到。
- 半传输中断被关掉（`__HAL_DMA_DISABLE_IT(huart6.hdmarx,DMA_IT_HT)`），只在"空闲/整包"时进一次回调。
- 两个 HAL 回调放在 `Core/Src/main.c` 的 `USER CODE BEGIN 4`，按 `huart->Instance == USART6` 分发。

### 5.2 帧格式

```
<地址 0xC8> <长度> <类型> <数据...> <CRC8>
```

- `长度` = 类型 + 数据 + CRC 的字节数（不含地址和长度本身）。
- `RC_CHANNELS_PACKED = 0x16`：22 字节数据 = 16 通道 × 11bit，整帧 26 字节。
- `LINK_STATISTICS = 0x14`：上行/下行 RSSI、LQ、SNR、发射功率、射频模式、天线。
- `HEARTBEAT = 0x0B`：心跳计数。
- CRC：CRC8/DVB-S2，多项式 0xD5，初值 0，非反射，查表实现（`RC_CRC`）。
  **覆盖范围是"类型~数据"（`&Input[2]`，长度 `frame_len-1`），CRC 字节在 `Input[frame_len+1]`**。

### 5.3 接口

```c
extern rc_data_t RC_Data;                       // 解析结果
extern uint8_t   RC_RxBuffer[RC_BUFFER_SIZE];   // DMA 目标缓冲（64 字节），只读
void Receiver_Start(void);                      // 挂一次接收（Hardware_Init 里调用）
void Receiver_Parse(uint8_t *Input,uint16_t size,rc_data_t *Output);
bool Receiver_Status(void);                     // 200ms 内收到过有效帧
```

`rc_data_t` 里：`CHANNEL[0..15]`（原始 172~1811）、摇杆量 `Left_X/Left_Y/Right_X/Right_Y`（-100~100，`Left_Y` 0~100）、
`S1/S2`（0~100）、`Button_A/B`、`Lever_A~D`、链路统计字段、`HEARTBEAT_COUNTER`。

### 5.4 真机验证（还没做）

接收机接好（ELRS 的 **TX → PC7**，共地），在 `PROTOCOL` 任务里加一行：

```c
printf("rc:%d %d %d %d link:%d\r\n",
       RC_Data.CHANNEL[0],RC_Data.CHANNEL[1],RC_Data.CHANNEL[2],RC_Data.CHANNEL[3],
       Receiver_Status());
```

- 打杆看 0~2047 变化、拔接收机电源看 `link` 在 200ms 内变 0。
- **如果一帧都进不来**，第一个怀疑 CRC 覆盖面：把 `RC_CRC(&Input[2],Input[1]-1)` 改成
  `RC_CRC(Input,Input[1]+1)`，比较位置改成 `Input[Input[1]+1]`… 这是一行的事，能立刻分辨是 CRC 约定问题还是接线问题。

### 5.5 失控判定与链路质量的分工（`Receiver_Status()` 别删）

- `Receiver_Status()`（本地超时）管：接收机掉电、杜邦线松、UART/DMA 卡死。这些故障下 CRSF 的 LQ 会永远停在最后一次的值（通常是 100%），看起来一切正常。
- `UPLINK_LINK_QUALITY` 管：飞机飞出范围。此时帧可能还在发（ELRS 配成"给固定值"时），超时永远不触发。
- 两个都要，谁都替代不了谁。后续做失效保护时：`LOST` 用超时、`DEGRADED` 用 LQ。

## 6. OSD（AT7456E，NTSC）

- 挂 SPI2，CS=PB12；`gpio.c` 里 CS 上电初始电平是**高**（CubeMX 里也设成 SET）。
- **没有 ID 寄存器**，检测只能靠写-读回：复位 → 写 `VM0=0x08` → 读回比较，5 次重试。
- `AT7456E_Init`：`VM0 = NTSC|AUTO|DISPLAY_ON|OSD_ON`，然后清屏（16 行 × 30 列 = 480 字节显存，逐字节写 `DMAH/DMAL/DMDI`）。
- 没接视频信号时 `STAT` 的 LOS 会置位，属正常；此时 OSD 叠加不出东西，必须接摄像头 + 显示屏才能看到画面。
- `AT7456E_WriteChar(Device,Row,Col,Ch)`：`Row` 0~15、`Col` 0~29、`Ch` 是字符表索引（`0x00` = 空白）。
  **目前没有消费者**，所以屏幕上还什么都不会显示。
- 字符表在芯片内部 ROM，写进去的是索引不是 ASCII。

## 7. 电机输出（DShot300）

引脚和定时器：

| 电机 | 引脚 | 通道 | DMA 流 | 句柄 |
|---|---|---|---|---|
| M1 | PB0 | TIM3_CH3 | DMA1_Stream2 | `hdma_tim3_up` |
| M2 | PB1 | TIM3_CH4 | DMA1_Stream2 | `hdma_tim3_up` |
| M3 | PA0 | TIM2_CH1 | DMA1_Stream3 | `hdma_tim2_up` |
| M4 | PA1 | TIM2_CH2 | DMA1_Stream3 | `hdma_tim2_up` |

**一个定时器只用一条流**：TIM3 那条负责 M1/M2，TIM2 那条负责 M3/M4。
不要退回"一路一条流"——两条流抢同一个 `TIMx_UP` 会相对错位，见 7.2 第 3 条。

- TIM2/TIM3：PSC=0、ARR=399、PWM mode 1、CCR 预装载开。内核 120MHz → 300kHz，一位 **3.333µs**（DShot300）。
- 一帧 16 位：11 位油门 + 1 位遥测 + 4 位 CRC，
  `CRC = (数据 ^ 数据>>4 ^ 数据>>8) & 0x0F`，帧 = `(数据<<4) | CRC`，MSB 先发。
- 数据位：`MOTOR_BIT0 = 150`（高 1.25µs，37.5%）、`MOTOR_BIT1 = 300`（高 2.5µs，75%）；`CCR = 0` 输出常低，这就是帧间空隙。
- 缓冲区 `uint32_t Motor_Buffer[2][256]`：每路 64 个周期，**16 个数据周期 + 48 个 0**，一帧 213µs，帧率约 4.7kHz。
  每个周期 4 个字，按突发顺序对应 CCR1~CCR4：
  - `[0][4i+2]` = M1（TIM3_CH3）、`[0][4i+3]` = M2（TIM3_CH4）
  - `[1][4i+0]` = M3（TIM2_CH1）、`[1][4i+1]` = M4（TIM2_CH2）
- DMA 用定时器自带的**突发模式**：目标固定写 `TIMx->DMAR`（`PeriphInc` 关），
  `DCR` 里 `DBL=3`（4 拍）、`DBA = CCR1 偏移 >> 2`，由定时器的地址发生器把数据依次分发到 CCR1~CCR4。
  一次更新请求写满四个 CCR，两个通道同一拍生效，不会互相错位。
  其余配置：`TIMx_UP` 请求 + Circular + **32 位** + FIFO 满阈值 + `MBURST/PBURST = INC4`，启动一次永久循环，不用中断。
- **DMA 缓冲必须放 RAM_D2**：DTCM（0x20000000）**不能被 DMA 访问**，而本工程的 `.data/.bss` 全在 DTCM。
  链接脚本加了 `.dma_buffer (NOLOAD) > RAM_D2` 段，缓冲定义加 `__attribute__((section(".dma_buffer")))`；
  NOLOAD 段启动代码不清零，`Motor_Init()` 里自己 `memset`。
  `RC_RxBuffer` 也一起挪了——它原来在 DTCM，真机上 USART6 的 DMA 会直接失败（一直没测过所以没暴露）。

### 7.1 CubeMX 里这两个 DMA 流必须是这个配置

`hdma_tim2_up`（DMA1_Stream3）和 `hdma_tim3_up`（DMA1_Stream2）**参数完全一样**，
而且是生成代码，只能在 `.ioc` 的 DMA 面板里改——手改 `tim.c` 下次生成就没了（已经栽过一次）：

| 字段 | 值 |
|---|---|
| Mode | Circular |
| Data Width（Peripheral / Memory） | **Word / Word** |
| Increment Address（Peripheral / Memory） | **不勾** / 勾 |
| Priority | Very High |
| FIFO Mode 与 Threshold | **Enable / Full** |
| Burst Size（Peripheral / Memory） | **Increment 4 beats** |

验证方法：生成后 `tim.c` 里这两段应各含 6 行关键配置
（`PDATAALIGN_WORD`/`MDATAALIGN_WORD`/`FIFOMODE_ENABLE`/`FIFO_THRESHOLD_FULL`/`MBURST_INC4`/`PBURST_INC4`）。
上板后在调试器里读 `DMA1_Stream3->CR`，正确值是 **`0x00035541`**。

### 7.2 踩过的三个坑（都已在代码里修掉，别改回去）

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | 非零油门电调毫无反应 | `Motor_Set()` 先算 `Frame` 后赋 `Check`，CRC 半字节恒为 0 | 先算 `Check` 再拼 `Frame` |
| 2 | PA0/PA1 **恒高**，CCR 读回 `0x012C012C` | TIM2 的 CCR 是 **32 位**寄存器；DMA 用 16 位写时 **AHB-APB 桥把数据复制到高、低两个半字** | DMA 改 `PDATAALIGN_WORD` / `MDATAALIGN_WORD`，缓冲区改 `uint32_t` |
| 3 | 每帧丢一个位槽，`f_min` 掉到 149.7kHz（正好 2 个位周期） | 一个定时器的两路用两条流，**抢同一个 `TIMx_UP` 请求**，偶尔丢一个请求 → 两条流相对错位一格 | 一个定时器一条流 + `DCR`/`DMAR` 四拍突发 |

判据与教训：

- 坑 2 认 `CCR = 0x012C012C`（两个 300 拼一起）、`0x015E015E`（两个 350）：**高半字和低半字重复**，就是 16 位写打进了 32 位寄存器。
  TIM3 是 16 位定时器、CCR 只有 16 位，不会中招，所以同一个 bug 只坏 TIM2 的两路，
  极易误判成"探针没接好"或"寄存器配错了"（实际上 `SxCR/PAR/M0AR` 一路都对）。
- 坑 3 认"缓冲区内容完全一样、但只有每个定时器的**第二路**波形有 6.68µs 空隙"。
  缓冲区一样而输出不一样，就只能是 DMA 搬运的问题。
- 排查时最有效的手段是把 `SxCR / PAR / M0AR / NDTR / LISR / HISR` 全打出来。
  寄存器全对但硬件不对，问题一定在"传输宽度"或"请求竞争"这类语义上，不是参数写错。
- 反例：中途试过"4 拍突发直接写递增的 CCR 地址"，流只完成第一次突发就停了（CCR 被锁在首拍值，
  表现为 M3/M4 恒输出首拍的占空比、M1/M2 恒低）。递增 APB 地址的突发不可靠，必须走 `DMAR`。

### 7.3 上电顺序与接口

`Motor_Init()`：`memset` → `Motor_Stop()`（**先发油门 0**）→ 配 `DCR` → 启动两条流 → 启动四路 PWM。
上电第一帧必须是油门 0，绝不允许出现满油帧。

- 接口：`Motor_Init()`、`Motor_Stop()`、`Motor_Set(Index,0~1000)`。
  油门映射：`0` → DShot **0**（帧 `0x000`，停转命令）；`1~1000` → DShot `48~2047` 线性映射；`>=1000` → `2047`。
  0 和 48 之间是有意的空档（停转 / 最小油门），不要合并。
- **不要在 `main()` 里加 `Motor_Set(x,1000)` 之类的试转代码**：这类残留曾把满油帧写满缓冲区，
  让整套自检读数全部失真（排查方向被带偏好几个小时），而且上电 3 秒后四路满油非常危险。试转用调试器或上位机命令。
- 还没做：状态机（DISARM/ARM）、失效保护、电池电压检测、PID。

## 8. IMU 六面朝向（重要）

NED 坐标：X 箭头/机头，Y 右，Z 下。
`Hardware` 里 `Ax=-rawX, Ay=-rawY, Az=+rawZ`：ICM42605 原始 X/Y 与板子 NED 反向，取反后得到 NED。

实际安装：箭头面（背面）朝上，箭头指机头；上位机姿态"飞机正放"= 板子箭头面朝上。

| 面 | 物理朝向 | 加速度读数（AHRS 比力向上约定） |
|---|---|---|
| FACE1 | +Z 朝下（箭头面/背面朝上，平放） | -Z |
| FACE2 | -Z 朝下（元件面/正面朝上，倒扣） | +Z |
| FACE3 | +X 朝下（箭头/机头侧朝下） | -X |
| FACE4 | -X 朝下（机尾侧朝下） | +X |
| FACE5 | +Y 朝下（右侧朝下） | -Y |
| FACE6 | -Y 朝下（左侧朝下） | +Y |

`AHRS.c` 期望水平时 `Acc=(0,0,-g)`（比力向上），所以校准的 Plus 取加速度为 `+g` 的面：
`Plus={3,5,1}`（FACE4/6/2）、`Minus={2,4,0}`（FACE3/5/1）。
如果实际翻面与上表不同，IMU 校准后姿态会翻/漂，需要交换映射。

## 9. 校准流程

### 9.1 IMU

1. 先把 FACE1（箭头面朝上）放好，点 Start。
2. `CHECK`：静止 500ms。
3. 自动采 FACE1：稳定 500ms + 500 点。
4. 进入 `WAIT FACE2`；翻面后点 NEXT。
5. 重复到 FACE6；进入 `WAIT GYRO`，放稳后点 NEXT。
6. 采 3000 点陀螺；计算 `Acc_Bias`、`Acc_Scal`、`Gyr_Bias`；回 `CAL,IMU,DONE`。

### 9.2 MAG

- 1000 点 @100Hz（约 10 秒），记录三轴 min/max；
- 每轴范围 > 100 LSB，否则 `ERROR`；
- 零偏 = `(min + max) / 2`，只做硬铁。

### 9.3 BAR

不做校准，只读压力和温度；上位机 BAR 校准列已隐藏。

### 9.4 Flash 参数

- 链接脚本 `FLASH` 改为 1920K，最后 128KB 留给参数；
- 单槽：`0x081E0000`，bank2 sector7；
- 每条记录 64 字节，CRC32 保护前 56 字节（`Flash.c` 里软件实现，多项式 0xEDB88320）；
- `Flash_Load()` 在 `main()` 里 `Hardware_Init()` 之后、`Task_Init()` 之前调用（当前是**启用**状态）；
- IMU/MAG `DONE` 后调用 `Flash_Save()`；写入回读失败会清校准标志并回 `SAVE,ERROR`；
- 单槽没有旧备份，擦写期间掉电会丢失校准，上电按未校准处理；
- CubeMX 不需要配 Flash 扇区；用 CubeProgrammer 确认 `SWAP_BANK` 关闭、bank2 sector7 没有写保护；
- 保存时会擦 bank2，所以代码应保持在 bank1（前 1MB）；当前程序约 103KB，远低于这个限制。

## 13. 飞行控制（User/Flight）

### 13.1 结构

分两层，和姿态解算同一套写法：`Task.c` 里只放 1kHz 的胶水，算法本身是纯函数。

| 层 | 位置 | 职责 |
|---|---|---|
| `FLT_Ctrl()` | `Task.c` | dt 保护（0.8~1.2ms 之外直接丢弃）、调用 `Flight_Update()` |
| `Flight_Update()` | `Flight.c` | 角速度误差 → PID → 混控 → 限幅 → `Motor_Set()`，不碰硬件、不读时间 |

校准后的机体系数据在 `HW_Body`（`Hardware.h`）：`AHRS_Est` 每毫秒算一次，
姿态解算和飞行控制共用同一份，避免两处各扣一次零偏。
`FLT_CTRL` 必须注册在 `AHRS_EST` **之后**，否则拿到的是上一周期的数据。

**`DISARM` 必须是 0**：静态变量零初始化就是上锁态，任何漏调 `Flight_Init()` 的路径都不会把飞机当解锁。

| 接口 | 作用 |
|---|---|
| `Flight_Init()` | 清状态/油门/杆量/积分，**并调用 `AHRS_Init` / `PVRS_Init` / `Height_Init` 三个算法初始化**；`main.c` 里紧跟 `Motor_Init()` |
| `Flight_Update(Gx,Gy,Gz,dt)` | 纯算法入口：自稳外环 → 角速度 PID → 混控，由 `FLT_CTRL` 调用 |
| `Flight_Stick(Thro,Yaw,Roll,Pitch)` | 遥控输入：油门 0~1000，杆量 −100~100（虚拟遥控/将来 CRSF 都走这里） |

> `Flight_Init()` 同时是**解锁入口**：`Protocol.c` 收到 `arm,<0|1>` 会先调它再改 `State`，
> 所以每次解锁/上锁三个算法都会重置一次——PVRS 位置归零（相对起飞点，正好是想要的）、
> AHRS 四元数回单位（地面上姿态本来就接近 0，但**别在空中调 `Flight_Init()`**）。

三个状态：`ARM` / `DISARM` / `FAILSAFE`。
`DISARM`/`FAILSAFE` 调 `Motor_Stop()`（DShot 0）；`ARM` 后输出 `怠速 + 油门` 再叠加姿态修正。

解锁：直接把 `State` 改成 `ARM`（调试器或 `Simulator_Init()`），没有单独的解锁函数。
不把上一次的残留带进环里。运行中只看**陀螺**健康，掉线直接进 `FAILSAFE`——
加速度计故障不该有停电机的权限（角速度环也不需要它）。

### 13.2 混控表（首转方向不对，只改这里）

标准 X 型，`Mix_Table[4][3]` 行是 M1~M4、列是 Yaw/Roll/Pitch（全工程统一这个顺序，别写成 Roll/Pitch/Yaw）：

| | Yaw | Roll | Pitch | 位置 | 桨向 |
|---|---|---|---|---|---|
| M1 | -1 | -1 | **+1** | 前右 | 顺时针 |
| M2 | +1 | -1 | **-1** | 后右 | 逆时针 |
| M3 | -1 | +1 | **-1** | 后左 | 顺时针 |
| M4 | +1 | +1 | **+1** | 前左 | 逆时针 |

- Yaw 右转 → 逆时针桨 M2/M4 加油
- Roll 右倾（右侧下沉）→ 左侧 M3/M4 加油
- Pitch 抬头 → **前侧 M1/M4 加油**（后侧加油是压机头）

> **踩过的坑：Pitch 列符号反了会变成正反馈。**
> 一开始配成"Pitch 抬头→后侧 M2/M3 加油"，物理上是压机头，和 `AHRS` 的"Pitch 抬头为正"相反：
> 给定 +100°/s 后机头反而下沉 → 陀螺反馈符号也反 → 误差越来越大 → 俯仰角速度冲到 **2600+°/s**、机体翻滚、永远趴地。
> 仿真日志里认这个特征：**`gy` 绝对值上千、高度恒为 0**。修正后 |gy| 只有 0.2°/s，滚转峰值 121°/s、高度正常爬升。

### 13.3 增益与限幅

**`Flight` 的可调参数在 `Flight.h` 顶部**；混控表和 PID 增益是 `Flight.c` 里的 `static const`；
PID 自己的限幅宏在 `PID.h`。

PID 本身是通用模块 [`User/Alg/PID.c`](../User/Alg/PID.c)：`pid_t` 一个结构体带 Kp/Ki/Kd、积分累计和微分历史，
对外只有 `PID_Init()` / `PID_Update(Target,Actual,dt)`。
**积分限幅 `I_LIMIT`、输出限幅 `O_LIMIT` 是 `PID.h` 里的宏**，不随实例变，所有环共用。
`PID_Init()` 顺带把 `Iterm`/`Last` 清零，所以它也是复位入口——解锁时重跑一遍即可，不需要单独的 `PID_Reset()`。
`Flight.c` 里放三个实例（Yaw/Roll/Pitch 角速度环），以后做高度环、位置环可以复用同一个模块。

> **坑：`Pid->Last = Err` 必须放在算完输出之后**。提前更新会让 `Kd*(Err - Last)/dt` 恒等于 0，微分项静默失效，波形上完全看不出来。
>
> **已知约束：`pid_t` 和 POSIX 同名**。`<sys/types.h>` / `<unistd.h>` 里也定义了 `pid_t`（newlib 是 `short`），
> 只要同一个目标文件里引入过那两个头，编译就会报 `conflicting types for 'pid_t'`。
> 目前全项目没有任何文件引入它们，所以安全；但 `PID.c` / `Flight.c` 的包含链里**不要**加 `unistd.h` 或 `sys/types.h`，
> 要加就先把这个类型改名。

| 参数 | 位置 | 值 | 说明 |
|---|---|---|---|
| `MIN_THRO` | `Flight.h` | 1 | 最低输出，0 会被电调理解成停转 |
| `MAX_THRO` | `Flight.h` | 1000 | 最高输出 |
| `MIX_GAIN` | `Flight.h` | 400 | 姿态修正最多占 400/1000 行程 |
| `ANGLE_KP` | `Flight.h` | 8 | 自稳外环增益（角度误差 → 角速度指令） |
| `MAX_ANGLE` | `Flight.h` | 35° | 满杆目标倾角 |
| `MAX_RATE` | `Flight.h` | 200°/s | 满杆角速度（偏航 + 外环限幅） |
| `Kp` / `Ki` / `Kd` | `Flight.c` | 见文件 | Yaw `0.0053/0.0027/0`，Roll/Pitch `0.0040/0.0013/0`（按 Tmax=9N 缩放）；D 默认关（1kHz 对陀螺噪声敏感） |
| `I_LIMIT` / `O_LIMIT` | `PID.h` | 0.30 / 1.00 | 积分限幅（±30%）、输出限幅（±100%），所有环共用 |

PID 输出是"混控权限"（±1 打满 `MIX_GAIN`）。饱和处理一行搞定：

```c
Scale = fminf(1.0f,(1000.0f - MIN_THRO)/(MaxDiff - MinDiff));
```

跨度小 → 系数 1（乘了等于没乘）；跨度大 → 等比压到可用行程（保姿态优先），再平移 `Base` 落进
`MIN_THRO~1000`。跨度是 0 时除零得 `+inf`，`fminf(1,+inf)=1`，不会出 NaN。
平移会把基准油门顶高（大修正时无人机会自己加油），这是有意的取舍：保姿态优先于保高度。

> **坑：压缩系数必须只算一次**。曾经写成 `MaxDiff *= 1000/(MaxDiff-MinDiff)` 之后再用同一个表达式算
> `MinDiff`，分母已经被改掉了 → 四个修正量被不同系数缩放，力矩比例失真，压缩也压不到位。

`Motor_Set()` 写缓冲区时可能和 DMA 读撞车，个别帧 CRC 错被电调丢弃——这是允许的，
按 1kHz 更新算大约每 20 帧丢 1 帧，电调完全能接受（它们只要几毫秒内有一帧合法）。

### 13.4 台架验证步骤（必须拆桨）

没有上位机命令，靠**调试器 + 逻辑分析仪**：`State`、`RC_SetThro`、`RC_SetYawRate`、`RC_SetRoll`/`RC_SetPitch`
都是 `Flight.c` 里的变量，`-g3` 编译后调试器能直接读写。

1. 上电：四路是 DShot 0 的 16 个等宽窄脉冲（见 7.3），此时 `Motor_Stop()` 在跑。
2. 解锁（`State = ARM`）。四路升到怠速（DShot 约 147），分析仪上应看到 16 个脉冲全变宽到 2.5µs 附近。
3. **验证自稳**：把 `RC_SetRoll` 设成 `50.0f`（目标倾角 17.5°）。
   静止时机身水平 → 角度误差 17.5° → 角速度给定 140°/s → 修正 240/1000。
   **M3/M4 变宽、M1/M2 变窄**，且基准油门会被顶高（见 13.3）。
4. 设成 `-50.0f` 反向验证；`RC_SetPitch` 同理（加油的是前侧 M1/M4）。
   偏航走 `RC_SetYawRate`（°/s），只动 M2/M4（逆时针桨），四个值差异更小。
5. **符号判据**：手持机身绕某轴快速转动（模拟"机体歪了"），外环应该让对应输出反向修正，
   即"想把它转回水平"。
6. `State = DISARM` → 立刻回 DShot 0，四路恢复等宽窄脉冲。

> 想看**纯角速度环**（跳过外环）：临时把 `ANGLE_KP` 设成 `0`，这时 `RC_SetRoll` 不再起作用，
> 只能靠 `RC_SetYawRate` 那样的直接角速度给定量验——不推荐，正常调试走第 3 步就行。

### 13.5 虚拟遥控输入（Flight_Stick）

原本打算做气压计高度环，2026-11-08 改成更接近真实用法的一步：**把上位机两个虚拟摇杆当接收机**，
`rc,<油门>,<偏航>,<横滚>,<俯仰>` 50Hz 灌进 `Flight_Stick()`，写 `RC_SetThro` / `RC_SetRoll` / `RC_SetPitch` / `RC_SetYawRate`——
和将来 CRSF 通道接进来走**同一套 setpoint**，控制逻辑一行不用改。高度环（`Height.c`）已删除。

| 项 | 值 / 说明 |
|---|---|
| 杆量范围 | 油门 0~1000‰（中位 500 = 定高）；偏航/横滚/俯仰 −100~100（百分比） |
| 满杆速率 | `MAX_RATE = 200 °/s`（`Flight.h`） |
| 映射关系 | 杆量 → `RC_SetYawRate`（偏航角速度）+ `RC_SetRoll`/`RC_SetPitch`（目标倾角比例）+ `RC_SetThro`（升降速度） |
| 超时回中 | **代码和宏都已删除**（用户明确不要），上位机断开后固件保持最后一帧杆量；接 CRSF 时必须重新加 |

上位机侧是美国手（Mode 2）：**左杆油门↑↓/偏航←→，右杆俯仰↑↓/横滚←→**；
左杆纵向不回中（油门保持），右杆松手回中，偏航也回中。

### 13.6 角度环（自稳，2026-11-09）

串级：**外环角度 P → 内环现有角速度 PID**，内环一行没改。

```
摇杆 → 目标倾角(±MAX_ANGLE) ──┐
                              ├─ 角度误差 × ANGLE_KP = 角速度给定量 → 角速度环 → 混控
AHRS 估计倾角 ────────────────┘
```

| 项 | 值 / 说明 |
|---|---|
| 满杆倾角 | `MAX_ANGLE 35°` |
| 外环增益 | `ANGLE_KP 8.0 /s`（角度误差 1° → 8°/s 给定量） |
| 限幅 | 角速度给定量仍限 ±`MAX_RATE`(200°/s) |
| 切换 | **常开**（2026-11-09：新手先用自稳，取消模式切换，代码里没有 `Angle_Mode` 开关） |
| Yaw | **不参与角度环**，一直是角速度（自稳只平滚转/俯仰） |
| 增益来源 | 离线复现整机模型扫的：`ANGLE_KP` 2/4/6/8/10/14 全部零超调，8 对应 0.32s 稳定 |

仿真验证（杆量 50% → 目标 17.5°）：

| ANGLE_KP | 峰值 | 超调 | 稳定 |
|---|---|---|---|
| 4 | 17.49° | −0.01° | 0.68 s |
| **8** | 17.50° | 0.00° | **0.32 s** |
| 14 | 17.50° | 0.00° | 0.19 s |

> 注意：自稳依赖 AHRS 估计准确。之前估计漂 20~70° 时做角度环会直接飞翻，
> 所以先把加速度计门控和 `KP_ACC` 调好（见 §16 踩坑记录），现在估计误差 1.8° 中位。

### 13.7 定高（Height.c，2026-11-09）

**油门杆当"升降速度"用，杆子自动回中**（DJI 那种定高手感）：

```
杆量中位 500‰（±DEADBAND 死区） → 升降速度 0 → 定高
往上打 → 上升，打得越多越快（满偏 MAX_VZ）
往下打 → 下降
松开回中 → 保持当前高度
```

所以"推上去升、松手停住、往下打才降"这三件事同时成立——**这是定高唯一自洽的摇杆语义**。
（之前试过"杆量=目标高度""只增不减""中间定高满杆爬"，都会出现"松开就反弹"或"根本降不下来"。）

| 项 | 值 / 说明 |
|---|---|
| 控制律 | `Out = HOVER_THRO + Speed_Z·ALT_FF + ALT_KP·(SetAlt−ActAlt) − ALT_KD·(Rate_Z−Speed_Z)` |
| 参数宏 | `MAX_VZ 150`(cm/s) `MAX_UP 500`(cm) `DEADBAND 20`(‰) `IDLE_THRO 50`(‰) `HOVER_THRO 421`(‰) |
| 增益 | `ALT_FF 0.05`、`ALT_KP 0.25`、`ALT_KD 1.20`、`ALT_SLEW 4000‰/s` |
| 滤波 | `LP_ALT 0.10s`、`LP_RATE 0.05s`，宏 `LPF(现在,上次,τ,dt)` |
| 限幅 | `ALT_ERR_MAX 200cm`、`ALT_RATE_MAX 200cm/s`、`CLAMP(值,限)` |
| 目标 | `SetAlt += Speed_Z·dt`，限制 0~MAX_UP |
| **落地停机** | `SetAlt<2 && ActAlt<5 && Speed_Z<=0` → 输出 `IDLE_THRO`（**必须保留**：不然地面上就被 421‰ 悬停油门抬起来，实测油门 420‰、贴地 0.3cm 蹭） |
| 输入 | `HW_Sample.Pressure`（Pa）——真机 `BAR_Read()` 写，仿真 `Simulator()` 按 ISA 写，同一条路 |
| 地面零点 | `ZeroAlt`：上电第一次气压非 0 时记下（`DPS310_Init()` 只初始化芯片不读数，所以不能在 `Height_Init()` 里取） |

**变量**：`Speed_Z`(升降速度指令) `ZeroAlt`(零点气压) `Rate_Z`(实测升降率) `SetAlt`(目标高度) `ActAlt`(滤波高度) `LastThro`(上次油门)

> **2026-11-11 重调**（"油门比较肉"）：`MAX_VZ` 60→**150 cm/s**（原来满杆才 0.6 m/s），
> 增益按 150 重扫（离线模型，与 §15.5 同一套机体参数）：`ALT_FF` 0.22→0.05、`ALT_KP` 0.60→0.25、
> `ALT_KD` 1.00→1.20、`LP_ALT` 0.15→0.10。
> 结果：满杆 1.5s → 稳定在 **228cm**（原来 90cm），超调 **6.6%**，松手时爬升率 158cm/s。
> 前馈不能大：0.22 时满杆会多给 33‰ 油门，冲上去再被压回来，超调 30%+。

**上位机解锁/上锁**：点按钮发 `arm,1` / `arm,0`；**固件的解锁状态放在遥测最后一列**（`SIM,...,<0|1>`），
上位机 50Hz 跟着它刷新按钮——解锁浅绿、上锁浅红，84×26 居中。
这样"点了没反应"只有一种可能：**命令没到固件**（没连上 / 固件没烧 / 端口选错）。

**自动化测试结果（8/8 通过，±1.6cm 气压噪声）**：

| 测试 | 结果 |
|---|---|
| 上电中位：电机不转 | 油门 1.0‰，高度 0 ✓ |
| 满推 1s 后松手：升到并稳住 | 峰值 156cm → 稳在 120cm ✓ |
| 空中中位 20s：高度不漂 | 波动 **0.4cm**，漂移 −0.7cm ✓ |
| 空中往下打：能降下来 | 121cm → 0cm ✓ |
| 拉到底：落地并停机 | 高度 0，油门 1.0‰ ✓ |
| 乱打杆：空中油门不为 0 | 空中最低 220‰（不会断电机）✓ |
| 目标高度限幅 | ≤MAX_UP ✓ |
| 油门不超限 | 50~739‰ ✓ |

> 真机注意：`HOVER_THRO` 要按实际重量标定；气压计受温度/气流影响；长时间飞行气压漂移要重设零点。

## 14. GPS（User/GNSS）

从旧工程 `WZH0765/Flight_Control`（H723ZGT6）的 `Hardware/GPS.c` 移植过来，去掉 FreeRTOS 依赖。

代码独立成 `User/GNSS/`，但**初始化归板级层**：`Hardware.h` 里加了 `USE_GPS` 开关，
`Hardware_Init()` 末尾 `#ifdef USE_GPS GPS_Start(); #endif`——GPS 属于普通板级外设，
接收机和电机那类核心链路才在 `main.c` 里单独初始化。

### 14.1 结构

| 文件 | 说明 |
|---|---|
| `GPS.c` / `GPS.h` | 我们的代码：收包、拆句、填 `GPS_Data` |
| `minmea.c` / `minmea.h` | 第三方 NMEA 解析库（Kosma Moczek，WTFPL），**逐字移植，不要改** |

链路：**USART2**（PD5/PD6）+ 空闲中断 + DMA1_Stream4，115200 8N1。

DMA 和中断全部由 CubeMX 生成（`.ioc` 里 `Dma.Request4=USART2_RX`）：
`usart.c` 建 `hdma_usart2_rx` 并 `__HAL_LINKDMA`，`dma.c` 使能 Stream4 中断，
`stm32h7xx_it.c` 生成 `USART2_IRQHandler` / `DMA1_Stream4_IRQHandler`。
`Hardware_Init()` 里 `#ifdef USE_GPS` 调 `GPS_Start()` 发起一次接收，`main.c` 的 UART 回调里收完再重启。

> CubeMX **没有**在 `usart.h` 里生成 `extern DMA_HandleTypeDef hdma_usart2_rx;`，
> 而这行是 `it.c` 编译需要的，所以补在 `usart.h` 的 `USER CODE BEGIN Private defines` 里——重新生成不会丢。

数据接口：

```c
gps_data_t GPS_Data;        //Fix/SatNum/时分秒/经纬度/海拔/地速/航向/TimeStamp(ms)
```

`Fix`：0 未定位、1 二维、2 三维（`gpsFix_e`）。`TimeStamp` 是 `millis()`，判链路是否还活着用它。

### 14.2 和旧工程的两个差异（都是修 bug，不是移植失误）

1. **旧代码 RMC 的数据根本到不了输出**：`ParseData` 是 `GPS_ParseLine()` 的局部变量，每句都清零，
   而只有 GGA 分支会 `GpsData = ParseData` —— 也就是时间、地速、航向永远是 0。
   现在改成静态暂存 `GPS_Buf`，RMC/GGA 各自填完都提交一次。
2. **旧代码会丢掉整包**：`if(len == 0 || len >= GPS_LINE_MAX_LEN) return;` 拿"单行上限"去卡整包长度，
   1Hz 的 GPS 常常一次吐 4~6 句（300~500 字节），会被整包丢掉。
   现在按缓冲区上限判断，并且 `GPS_RxBuffer` 用到 `SIZE-1`，留一字节给 `'\0'`。

### 14.3 上板前要确认

- **波特率**：`usart.c` 里 USART2 是 CubeMX 默认的 115200；多数 GPS 模块出厂 9600。
  两者必须一致——要么在 CubeMX 改 USART2，要么用 u-center/AT 命令把模块改成 115200。
- 模块需输出 **RMC + GGA**（其它句子会被忽略，但会被解析库跳过，不影响）。
- 只在有校验和（`*hh`）时才接受：`minmea_check(line,true)`。
- CubeMX 重新生成时：`Hardware_Init()` 里那句和 `main.c` 回调都在 USER CODE 区，不会丢；中断处理函数是生成的，**不要再手写一份**（会重复定义）。
- GPS 目前还没上 OSD。

### 14.4 遥测（2026-11-11）

`Simulator()` 里每 100ms 打一行（**和 `SIM,` 挤在同一个任务里**，2026-11-11 从独立的 `GPS_SEND` 任务并进来的——坐标本来就是现成的，不值当再开一个任务）：

```
GPS,<fix>,<sats>,<lat*1e7>,<lon*1e7>,<alt_cm>,<speed_cm/s>,<course_deg>
```

| 项 | 说明 |
|---|---|
| 数据源 | 统一是 `GPS_Data`：真机由中断里的 `GPS_Parse()` 填，仿真由 `Simulator.c` 用模型 NED 位置填 |
| fix | **0 无定位 / 1 二维 / 2 三维**（和 NMEA 的 `fix_quality` 同一套编号） |
| 上位机 | `gps_page.py` 解析后画飞机标记 + 绿色轨迹；`fix < 2` 不画 |
| 仿真的坐标 | home 点固定 `SIM_HOME_LAT/LON`（上海人民广场），`N/111320`、`E/95200` 换算成经纬度 |
| **只在仿真里打** | 打印语句在 `Simulator.c`（整个文件被 `#ifdef USE_SIM` 包住），关掉仿真就没有 `GPS,` 了；以后接了真模块要在 `Prot_Run` 里另加一处 |

> 顺手修的坑：`gpsFix_e` 原来写的是 `GPS_FIX_2D`（=0）、`GPS_FIX_3D`（=1）、`GPS_FIX_INVALID = 0`——
> **2D 和 INVALID 撞成同一个值**，`Fix` 永远分不出"没定位"和"二维定位"。现在改成 0/1/2。

## 15. 固件仿真（User/Simulator）

没有电调、电机、遥控器时，用**板载自仿真**验证飞行代码：把"被控对象"也放进 MCU 里跑，
固件本身的 PID、混控、状态机、DShot 一行不改，跑的是同一份代码、同样的时序。

### 15.1 开关

**总开关在 `Simulator.h` 顶部**：

| 开关 | 作用 |
|---|---|
| `USE_SIM` | 打开后真实传感器任务不再注册、模型接管传感器；**注释掉则仿真代码整体不参与编译**（`Simulator.c` 变空文件），固件恢复真实外设行为 |

> `SIM_STEP`（自动 Roll 阶跃激励）已在 2026-11-08 删除：改成虚拟遥控后它是多余的，
> 而且它会每毫秒覆盖横滚指令，把摇杆输入冲掉——人工飞行时必须没有它。

规矩：**谁要判断 `USE_SIM`，谁就得 `#include "Simulator.h"`**——宏只在这个头文件里定义，没包含就看不到。
目前用到它的地方一共四处：

| 文件 | 用法 |
|---|---|
| `main.c` | `#ifdef USE_SIM` 包住 `Simulator_Init()`（在 `Flight_Init()`/`Flash_Load()` 之后） |
| `Task.c` | `#ifdef USE_SIM` 注册 1kHz 的 `SIMULATOR` 任务；`#ifndef USE_SIM` 才注册 `IMU_READ`/`MAG_READ`/`BAR_READ` |
| `Motor.c` | `#ifdef USE_SIM` 才记录 `SimuThro[]` |
| `Simulator.c` | 整个文件包在 `#ifdef USE_SIM` 里 |

> 仿真模式下 `GYR_Health` 不会被更新（没人调 `Health_Update`），`Count` 恒为 0 → `Health_Status()` 返回健康，
> 所以不会误进 `FAILSAFE`。这是对的，但要知道它为什么"永远健康"。

### 15.2 模型

| 部分 | 实现 |
|---|---|
| 姿态 | 四元数积分，公式与 `AHRS.c` 完全一致（便于对照估计值） |
| 角运动 | 力臂力矩 + 偏航反扭矩，单轴转动惯量 `SIM_INERTIA` |
| 电机 | 一阶滞后 `SIM_TAU`（20ms）+ 推力 ∝ 油门²（`SIM_TMAX`） |
| 线运动 | 推力沿机体 -Z、重力沿 NED +Z，NED 速度/位置积分 |
| 地面 | 触地清零速度；角速度每毫秒 ×0.98（τ≈49ms）。**没有地面自稳**，落地后姿态不会自己回平 |
| 阻力 | `SIM_DRAG 0.030 N/(m/s)²`，沿速度反方向、∝v²；没有它净推力一为正就一直加速往上窜 |
| 传感器 | 陀螺 = 角速度 + 噪声；加速度 = 机体系比力（水平时 `(0,0,-g)`）；磁 = NED 地磁转到机体系；气压按 ISA 由高度反算 |

**参数（`Simulator.h`，典型 5 寸机）**：`SIM_MASS 0.65kg`、`SIM_TMAX 9N`（满油推重比 **5.7**，5 寸机常见 5~8）、
`SIM_ARM 0.078m`（轴距 220mm）、`SIM_INERTIA 0.005`、`SIM_YAW_T 0.012`、`SIM_DRAG 0.03`。

**悬停点**：4×9N×u² = 6.37N → u = 0.421 → 基准油门 **421‰**，对应 `ALT_HOVER`。
油门杆现在是"升降速度"语义（中位 500‰ = 定高），所以没有"杆量=悬停油门"的映射了。

> `SIM_DRAG` 别调大：取 0.10 时阻力加速度会被加速度计当成重力的一部分，姿态估计偏 12~70°（踩过这个坑）。

### 15.3 时序

```
SIMULATOR(1kHz) → Simulator()  用【上一拍】的电机油门积分机体，再合成传感器
AHRS_EST(1kHz)  → 用合成数据解算姿态
PVRS_EST(200Hz) → 取 HW_Body.Acc 预测位置/速度；未解锁时补一次零速
FLT_CTRL(1kHz)  → 读角速度 → PID → 混控 → Motor_Set()  写 SimuThro[] 和 DMA 缓冲
```

`PVRS_Est` 排在 `AHRS_Est` 后面，因为它要用 AHRS 刚算出来的欧拉角把机体系加速度转 NED；
两者周期不同（1ms / 5ms），偶尔 PVRS 会先跑一拍、用上一毫秒的姿态，误差可以忽略。

`SIMULATOR` 注册成 `TASK_PRIORITY_REALTIME`，比 `AHRS_EST`/`PVRS_EST`/`FLT_CTRL`（HIGH）高，所以同一拍里一定先跑；
仿真模式下 `IMU_READ`/`MAG_READ`/`BAR_READ` 根本不注册。

用上一拍的油门是**故意的**：这样不构成代数环（油门→状态→传感器→油门），而且天然对应真实的电调延迟。

`SimuThro[4]`（定义在 `Simulator.c`，声明在 `Simulator.h`）记录 **DShot 编码前的模拟量油门**（0~1000）：
`Simulator.c` 拿它积分机体，`Motor_Set()` 里更新它。声明和那句赋值都在 `#ifdef USE_SIM` 里——
关掉仿真时这个变量根本不存在。

### 15.4 输出

USB CDC **每 10ms 一行（100Hz）**，15 个字段：

```
SIM,Roll×10,Pitch×10,Yaw×10,Gx×10,Gy×10,Gz×10,M1,M2,M3,M4,高度cm,解锁,北向cm,东向cm
```

姿态/角速度是 **×10 的整数**（避免 printf 浮点支持增大固件），单位分别 0.1° 和 0.1°/s。
最后两列是**水平位置（北/东，相对起飞点，cm）**，2026-11-11 加的，给虚拟地图用。

> 2026-11-11：原来是 1kHz 打，`printf` 占满 USB CDC（`CDC_Transmit_FS` 忙就丢帧），
> **飞久了数据流会断**、地图上的飞机就不动了。现在函数里用 `millis()` 分频到 100Hz。
> 曲线窗口 150 点 × 10ms = **1.5 秒**。

> **仿真模式下建议把 `USER_DEBUG_HOST_TOOL` 注释掉**，否则两种 CSV 混在同一个串口上不好分。
> `printf` 走 USB CDC，`CDC_Transmit_FS` 忙的时候**直接丢帧**（返回 BUSY，`_write` 不看返回值），
> 所以 1kHz 里能活下来的只是一部分——曲线和地图都不受影响，但别指望每帧都收到。

### 15.5 预期的结果（用当前增益算过）

**角速度环**（`Kp=0.004 / Ki=0.0013`，Tmax=9N）：100°/s 阶跃 → **40ms 到 100°/s**、
峰值 **114°/s（超调 14%）**、稳态 100.5°/s。

**自稳角度环**（`ANGLE_KP=8`）：右杆打一半 → 倾角 **17.5°** 后停住；松手 **0.32s 回平**，零超调。

**定高环**（`ALT_KP 0.25 / ALT_KD 1.20`，`MAX_VZ 150`，±1.6cm 气压噪声）：满推 1.5s 再回中 → 冲到 236cm 后稳在 **228cm**（超调 6.6%）；
稳定后油门波动 **±1‰**（曲线上看不出抖动）。

| 项 | 说明 |
|---|---|
| 数据格式 | `GPS,<fix>,<sats>,<lat*1e7>,<lon*1e7>,<alt_cm>,<speed_cm/s>,<course_deg>`（8 字段） |

| 缓存 | `~/.fc_osm_tiles/amap_z_x_y.png` |

### 15.7 能验证什么 / 不能验证什么

| 能验证 | 不能验证 |
|---|---|
| PID 三个轴的符号 | 电调真实响应 |
| 混控表 12 个正负号、桨向 | 桨叶气动、真实的转动阻尼 |
| 饱和处理（压缩 + 平移） | 机架振动谱（会影响 D 项） |
| 积分限幅 | 传感器真实噪声特性 |
| 状态机 DISARM/ARM/FAILSAFE | GPS 定位精度 |
| DShot 波形（定时器照常跑，可接逻辑分析仪） | 首飞增益（还要在真机收敛一次） |

> 模型里**没有气动阻尼**，所以 P 控制看起来"零稳态误差、几乎不衰减"——真实机体有阻尼，响应会不同。
> 这里只用来判断逻辑和符号，不是用来定最终增益的。

### 15.8 怎么用

1. 确认 `Simulator.h` 里 `USE_SIM` 打开，编译烧录
2. 上电后 USB 串口应先出现一行 `SIM,start`，之后每 20ms 一行 `SIM,...`
3. 打开上位机（用仓库里的 `.venv`）：`cd HostTool` → `..\.venv\Scripts\python.exe main.py`
4. 选串口 → 连接 → 点左侧 **`Simu`** 页
5. 点 **未解锁** 按钮（连上后才会变可点），变绿显示"已解锁"
6. **飞**：按住 W 上升，松开定住，按住 S 下降；右杆打俯仰/横滚，松杆自动回平
7. **看轨迹**：四张曲线下面是**虚拟网格地图**（北朝上，一格多少米看比例尺），
   飞机图标带着高度数字在飞，飞过的路留青绿线；拖地图=暂停跟随，双击=回到飞机，
   滚轮缩放；想看真实地图就切到 **`Gps`** 页

判读：解锁后按钮变绿、油门曲线到怠速 50‰；按住 W 油门平滑升到 400~450、高度稳步上升；
右杆打一半机身倾斜 17.5° 后停住，松手 0.3 秒回平；打横滚时「油门」图左右差速。
顶部读数栏直接给数字：`高度 299 cm  油门 421 ‰  姿态 +12 / -3`。

**交互：虚拟遥控（美国手）**

页面顶部是两格虚拟摇杆（都有四等分刻度）：

| 杆 | 上下 | 左右 | 键盘 |
|---|---|---|---|
| 左杆 | **升降速度**（中位=定高，**自动回中**） | 偏航（松手回中） | **W/S** 升降、**A/D** 偏航 |
| 右杆 | 俯仰（松手回中） | 横滚（松手回中） | **↑/↓** 俯仰、**←/→** 横滚 |

方向键：**↑ = 低头前飞**、↓ = 抬头；← 左滚、→ 右滚。这是 Mode 2 真遥控器的约定，不是反的
（低头 → 高度环自动补油门保持高度）。鼠标拖两个摇杆也行，松手同样回中。

上位机 50Hz 发 `rc,<高度>,<偏航>,<横滚>,<俯仰>`，固件 `Flight_Stick()` 写 `RC_SetThro` / `RC_SetRoll` / `RC_SetPitch` / `RC_SetYawRate`。
滚转/俯仰是**自稳**（角度环常开，满杆 35°），偏航仍是角速度（满杆 200°/s）。

解锁走 `arm,1` / `arm,0`；固件把解锁状态放在遥测最后一列（`SIM,...,<0|1>`），
上位机 50Hz 跟着它刷新按钮——**点了没反应只可能是命令没到固件**（没连上/端口选错/没烧录）。
